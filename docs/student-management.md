# 學生管理與名單匯入

教師在「學生管理」頁建立學生帳戶與班級。最常走的路是**匯入一份名單**，一次開好帳號順便分班。

- 前端頁面：`pages/StudentManagementPage.tsx`
- 名單解析（純函數）：`utils/student-roster.ts`
- API：`server/api/students.ts` 的 `POST /api/students/import`
- 單元測試：`npm run test:roster`；API 整合測試：`cd server && npm run test:students`（要 DB）

## 欄位規格

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| 姓名 | 是 | 空白時退回用 email 當顯示名 |
| 班級 | 否 | 例：`3A`、`5B`、`S3A`。填了就自動開班並分班 |
| 年級 | 否 | 只在班級欄沒有數字時用來拼班名（見下） |
| email | 是 | 學生登入帳號；同一份名單內不可重複 |

欄位順序任執，表頭中英文都認（`姓名/名字/學生姓名/name`、`班級/班別/class`、
`年級/grade/year`、`email/電郵/電子郵件`）。**沒有表頭**就退回舊行為：最後一格當 email，
前面全部當姓名，不設班級。

檔案格式收 `.xlsx`、`.csv`、`.tsv`、`.txt`，或直接在文字框貼上。分隔符認逗號、全角逗號、tab。

## 班級就是「年級＋班別」，不另設年級系統

香港老師習慣把年級與班別寫在一起（`3A`、`5B`），所以**系統沒有獨立的年級欄位**，
班級名就是唯一的班級身份。`users` 沒有 `grade` 欄，UI 也不分「年級」層。

班級欄與年級欄的合併規則（`mergeGradeClass`）：

- 班級欄**本身有數字** → 原封不動。`S3` + `S3A` → `S3A`（不會變成 `3S3A`）
- 班級欄只有英文字母 → 用年級的數字拼在前面。`P3` + `B` → `3B`、`3年級` + `B` → `3B`
- 年級沒有數字 → 直接用年級文字。`中一` + `B` → `中一B`
- **班級欄空白 → 不分班**。年級單獨存在不會變成班名，免得開出一個叫「3」的垃圾班

## 匯入行為

- **一次 1–500 行，全有或全無（transaction）**。任何一行出錯就整批 rollback，
  連同該次新開的班級一併收回——不會留下半份名單
- email 格式錯、或同一份名單內 email 重複 → **該行略過，其餘照匯入**，
  並在匯入前後都列出「第幾行、為什麼」給老師追
- 同名班級**重用**，不會重複開班（依 `teacher_id` + `name`，取最舊那個）
- 已在該老師名下的學生照樣匯入，只是不新開帳號；回報會分開講「幾位新帳號 / 幾位本來就有」
- email 大小寫不敏感（一律轉細寫再比對）
- 檔案上限 5 MB（前端先擋）

匯入後的預覽與結果摘要都會列出每班人數。**「每班人數」是該班總人數**，不是這一批匯入幾人
——重匯入時看得到班上實際有多少人。

匯入完成後前端**重新載入**學生與班級，不是自己拼接回應：新開班級的 id 只有 server 有，
而班級卡的成員是由 `group.studentIds` 推導出來的。

## 新帳號的初始密碼

新開的學生帳號一律用**同一個初始密碼**（`server/api/students.ts` 的
`DEFAULT_STUDENT_INITIAL_PASSWORD`，現值 `00000000`），不是逐個學生亂數產生。
所以匯入結果只會**講一次**密碼，不會逐個學生列一行——20 個新帳號列 20 行一樣的字只是噪音。

前端不 import 這個常數（server 程式碼不可進前端 bundle），也不硬編死它的值：
只要回傳的密碼全部一樣就收成一行；將來若改回逐個不同，畫面會自動逐個列出。

**學生暫時不能自己改密碼**（2026-09-24 決定，權限制度日後再統一處理）：帳戶由學校名單開立，
密碼由老師派發，所以匯入結果亦不再叫學生登入後改密碼。

- 前端：`pages/AccountPage.tsx` 的「修改密碼」表單對學生隱藏（老師照舊有）；
  學生版客服中心不再有「如何更改密碼」條目
- 後端：`PUT /api/auth/profile` 收到學生的 `newPassword` 就回 403——**只收埋 UI 唔算數**，
  API 直接打得到

學生**仍然**改得到電郵（同一個 route、同一個「安全設定」區塊）。學生帳號的電郵由學校派發，
改動會令下次匯入對不上，所以呢點遲早要一齊封——日後改權限時處理。

## Excel 範本

頁面上有「下載 Excel 範本」按鈕，產生的檔案表頭就是 `姓名, 班級, 年級, email`，
附三行示範資料。範本表頭與解析器的 alias 是同一套，所以填好直接上傳就匯入得到
（`tests/student-roster.test.mjs` 有 round-trip 測試守住這件事）。

## 已知限制

- **同一位老師同時匯入兩份名單，可能開出兩個同名班級**。`student_groups` 沒有
  `(teacher_id, name)` unique constraint，而目前的「先 SELECT 再 INSERT」不是 race-safe。
  單一老師逐次匯入（正常用法）不會遇到
- SheetJS（npm 的 `xlsx@0.18.5`）帶有已知 advisory，且 npm 上最後一版就停在 0.18.5。
  評估後仍採用：解析在**老師自己的瀏覽器**上、對老師自己選的檔案做，不碰伺服器；
  換成 SheetJS 官方 CDN tarball 會變成 URL 依賴，同事的 install 隨時會斷。
  它是**動態 import**，Vite 會切成獨立 chunk，老師不匯入 Excel 就不會下載
- 前端解析器（`utils/student-roster.ts`）刻意不寫任何顯示用中文——`tests/ui-i18n.test.mjs`
  只掃 `App.tsx`、`pages/`、`components/`，`utils/` 掃不到，寫了也沒人守。
  訊息一律由 page 傳入，或回傳 reason code 讓 page 翻譯
