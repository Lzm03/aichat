# 知識地圖多主題版本（Tab 架構）— UX/UI 設計

## 背景

老師需要同時上傳多個不同主題嘅教材文檔（例：英語語法第一課、英語閱讀第一課、
英語聽力第一課）。現時知識地圖係單一長列表，多檔提取全部堆疊埋一齊。
本設計將知識地圖改為「主題版本」Tab 架構：每份教材 = 一個主題版本（tab），
點選切換查看與編輯，唔再堆疊。

## 已拍板嘅關鍵決策

| 決策 | 結果 |
|---|---|
| 版本 vs 話題 | **版本 = 話題**（每版本喺 character_topics 一行；對話按話題用對應版本，機制已有） |
| 上限 | **每 Bot 最多 4 個**（MAX_TOPICS_PER_CHARACTER 唔郁；即最多 4 個 tab） |
| 多檔上傳 | **每檔自動一 tab**（檔名做版本名，預設 [單元課本]） |
| 分類標籤 | **預設四款 + 自訂**（自訂係帳戶層面，最多 10 個，跨 Bot 共用） |
| 對話側 | **按話題用對應版本**（現有 topic 切換機制照用；冇指定 → 默認版本） |
| 保留 | 新增知識點、mindmap/列表視圖、身份與說話風格跨版本共享（step 4 統一定義） |

## 1. Tab 列版式（知識地圖 tab 內容區頂部）

```
┌──────────────────────────────────────────────────────────────────────┐
│ 知識地圖                                                              │
│ 所有主題版本共用角色身份與說話風格（step 4 統一定義）                       │
├──────────────────────────────────────────────────────────────────────┤
│ ┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐ ┌──────┐ │
│ │ 英語語法第一課  ▾│ │ 英語閱讀第一課  ▾│ │ 英語聽力第一課  ▾│ │ ＋  │ │
│ │ [單元課本]   ✕ │ │ [補充講義]   ✕ │ │ [單元課本]   ✕ │ │新增  │ │
│ └─────────────────┘ └─────────────────┘ └─────────────────┘ └──────┘ │
│        ▲ 選中 tab：indigo 底線 + 分類 badge 著色                        │
├──────────────────────────────────────────────────────────────────────┤
│ 當前版本：英語語法第一課 │ [單元課本 ▾]（四選一 + 自訂輸入）│ 默認版本 ⭐   │
│                                                                      │
│  ○──○──○    知識點 mindmap／列表——原 UI 不變（編輯/刪除/拖動照舊）        │
│  ○──○                                                                 │
│  [＋ 新增知識點] ← 保留，喺當前選中版本內新增                             │
└──────────────────────────────────────────────────────────────────────┘
```

## 2. Tab 互動

| 動作 | 行為 |
|---|---|
| 點選 tab | 切換查看/編輯該版本知識點（列表+mindmap 只顯示當前版本） |
| ＋ 新增版本 | 手動開空 tab（rename 狀態）；滿 4 個時 ＋ 變灰 + tooltip「每隻 Bot 最多 4 個主題版本」 |
| 改名 | double-click 或 ▾ menu → rename；同步更新 topic name |
| 分類 badge ▾ | 預設四款 `[單元課本][補充講義][課外延伸][題庫對應]` ＋ 帳戶自訂標籤 ＋ 最底「＋ 自訂標籤…」（打字新增） |
| 刪除 ✕ | 確認對話框「刪除後呢個版本嘅知識點同學生覆蓋進度會一併移除」（同現有刪 topic 行為） |
| 排序 | 拖動 tab 換位（→ topic sortOrder） |
| 默認版本 ⭐ | 沿用 isDefault topic；學生開對話冇指定話題時用呢個版本 |

## 3. 分類標籤規則

- 預設四款：系統固定，唔可刪
- 自訂標籤：**帳戶層面**（跟老師，跨 Bot 共用，menu 重現），**最多 10 個**
- 滿 10 個：「＋ 自訂標籤」變灰 + tooltip「最多 10 個自訂標籤，可先刪除唔再用嘅」
- 每 tab 用一個標籤（預設任揀或自訂任揀）

## 4. 多檔上傳流程（分配方式 + 4 上限前置攔截）

```
老師揀 N 個檔
  │
  ├─ N = 1 → 直接提取入新 tab（現有流程）
  │
  └─ N ≥ 2 → 「分配方式」對話框：
        ┌──────────────────────────────────────────────┐
        │ 呢 N 個檔點處理？                              │
        │ ○ 各自獨立成版本    （每檔一 tab；需 N 個位）    │
        │ ● 合併為一個新版本  （N 檔一齊做一次提取）      │
        │ ○ 合併入現有版本    （揀：英語情境會話 ▾）      │
        └──────────────────────────────────────────────┘

  各自獨立成版本：
    → 上限檢查：現有 tab + N ≤ 4？
      ├─ 超咗 → 上傳前攔截：「每隻 Bot 最多 4 個主題版本。已有 M 個、
      │        揀咗 N 個檔。請刪除版本、揀少啲檔，或改用合併模式。」
      └─ OK → 逐檔提取，每檔完成即開新 tab（檔名做版本名、預設 [單元課本]），
              自動跳去最新 tab 檢查

  合併為一個新版本：
    → 上限檢查：現有 tab + 1 ≤ 4？
    → N 檔文字合併做一次提取（如 5 個英語情境 = 跨單元 → 6–20 點）
      · 合併後文字超長（超出模型 input 限制）→ 自動 fallback 逐檔提取再合併知識點
    → 開一個新 tab（老師改名，預設 [單元課本]）

  合併入現有版本：
    → 唔佔新位（0 slot）；逐檔提取，知識點合併入揀咗嗰個 tab：
      · title 匹配保留舊 id（assignStableKnowledgePointIds），新點追加
      · 同一概念唔會重複（title 相同當同一點，更新內容）
      · 總數照 20/10 上限 trim
```

**典型用例**：5 個英語情境文檔（點餐/購物/看病/打招呼/急救）揀「合併為一個新版本」
→ 一個 tab「英語情境會話」，入面一次過做晒知識點分析。

### 4.1 分配方式對話框 UX（模式發現性）

觸發時機：揀咗 N≥2 個檔、撳「開始解析」後、提取開始前彈出；N=1 喺當前版本
已有內容嗰陣都會彈（單檔變體），當前版本空（第一次上傳）先跳過對話框直接解析。

```
┌────────────────────────────────────────────────────────────┐
│ 開始解析前：呢 5 個檔案想點整理？                              │
│ 提示：唔同主題建議分開；同一主題嘅多個檔案可以合成一個版本        │
├────────────────────────────────────────────────────────────┤
│ ┌──────────────┐ ┌──────────────┐ ┌──────────────────────┐ │
│ │ 📄→📑        │ │ 📄📄📄→📑    │ │ 📄→＋               │ │
│ │ ● 各自獨立   │ │ ○ 合成一個    │ │ ○ 加進現有版本        │ │
│ │ 每檔一個版本 │ │ 新版本       │ │                      │ │
│ │              │ │              │ │ 加進：                │ │
│ │ 例：語法課＋  │ │ 例：5 個英語  │ │ [英語情境會話 ▾]      │ │
│ │ 閱讀課分開教  │ │ 情境合成一課  │ │                      │ │
│ │ 佔 5 個位 ⚠  │ │ 佔 1 個位 ✓  │ │ 佔 0 個位 ✓         │ │
│ └──────────────┘ └──────────────┘ └──────────────────────┘ │
├────────────────────────────────────────────────────────────┤
│ 結果預覽（跟住上面揀咗嘅即時變）：                            │
│  [英語點餐][英語購物][英語看病][英語打招呼][英語急救]          │
│  ⚠ 每隻 Bot 最多 4 個版本——呢個揀法會超上限，請揀「合成」或     │
│    減少檔案                                               │
├────────────────────────────────────────────────────────────┤
│                              [取消]  [開始解析]               │
└────────────────────────────────────────────────────────────┘
```

六個令老師「知道」嘅 UX 手法：

1. **選項卡用具體例子**，唔用抽象字眼——「例：5 個英語情境合成一課」比「合併模式」
   易明；「加進現有版本」直接顯示可揀嘅現有 tab 下拉
2. **即時結果預覽**：揀邊個 option，下面條預覽 tab 列就跟住變（各自→N 個 tab；
   合成→1 個 tab；加進→顯示合併後嗰個 tab）——老師喺撳掣前就睇到後果
3. **佔位顯示 + 超上限自動置灰**：每張卡寫明「佔 N 個版本位」；會超 4 上限嘅選項
   置灰 + 預覽度出警告（「呢個揀法會超上限，請揀合成或減少檔案」）——唔會揀咗先知錯
4. **記住上次選擇**：老師揀過「合成」之後，下次默認揀返佢，老手零思考 ✅（已實現）
5. **單檔跳過對話框**：N=1 且當前版本未有內容（第一次上傳）直接解析，唔煩；
   當前版本已有內容嗰陣，單檔都會彈框（單檔變體：開新版本／覆蓋當前版本／
   加進現有版本），避免靜靜雞覆蓋咗而家開緊嗰個 tab ✅（已實現）
6. **完成後反饋**：新 tab highlight 動畫 + toast「已建立 N 個主題分頁」／
   「已合併入『英語情境會話』」／「已填入／已更新」等，老師一眼知結果 ✅（已實現）

### 4.2 重複上傳（補 2026-09-19）

第一次上傳完成後，老師想繼續加新資料、生成第二個 Tag：

- **入口一（常駐）**：教材來源 tab 喺「已完成」狀態都保留拖拽區（上面係成功 banner +
  「前往知識地圖」，下面係「再上傳更多教材」拖拽區）——唔使撳「重新提取」先可以再上傳
- **入口二（捷徑）**：tab 列尾「上傳」按鈕，一撳跳去教材來源並直接開 file picker
- 上限前置檢查計埋「空嘅當前版本會被第一個檔填充」——唔會誤判超上限；
  4 個位滿嗰陣，合併/覆蓋模式仍然可用

核心原則：唔係靠老師預先「知道」有三個模式，而係喺嗰一刻用**例子＋預覽＋上限警告**
幫佢做啱決定。

## 5. 對話側（不變）

- 版本 = 話題（character_topics）；學生對話按話題用對應版本知識（現有機制）
- 冇指定話題 → 默認版本

## 6. 技術映射

- **DB**：`character_topics` 加 `category TEXT`（空＝[單元課本]）；上限 4 唔郁；
  自訂標籤存帳戶層面（新小表 `teacher_category_labels(teacher_id, label)` 或
  users JSONB 欄，實作時揀，上限 10 喺 code 執行）
- **前端**：`CreationStep2` 知識地圖加 `TopicVersionTabs` 組件（tab 列 + 分類 menu +
  自訂標籤管理）；多檔上傳改逐檔循環 + 4 上限前置檢查；每檔提取後經
  `utils/topic-api.ts` 建 topic（name=檔名、category=標籤）
- **TopicManager（step 4）**：同知識地圖 tab 列共用同一批 topic 數據，兩邊同步；
  step 4 收窄做話題細節（systemPrompt／獨立背景知識）編輯
- **保留**：新增知識點、mindmap/列表視圖、身份/說話風格共享

## 7. 實作階段建議

1. DB：character_topics.category + 自訂標籤儲存 + migration
2. `TopicVersionTabs` 組件 + CreationStep2 整合（切換/改名/刪除/排序/分類/自訂標籤/4 上限）
3. 多檔上傳流程改造（前置攔截 + 逐檔提取 + 自動開 tab）
4. TopicManager 同步收窄
5. 驗證：lint/test:i18n/test:ids/build + 真後端 topic CRUD 檢查
